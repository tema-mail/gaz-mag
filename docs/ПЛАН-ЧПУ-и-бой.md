Владелец: «сделай нормальную карту сайта и ЧПУ с правильной иерархией и названием товара, чтобы чётко по SEO;
товар завёл – адрес, title и description заполняются сами, без цифр и tproduct, в Болотном, а не в Новосибирске;
цепочку GitHub убирай, когда я говорю „выводим в бой“ – сейчас убирай».

- Адрес товара – транслит названия (ГОСТ-подобный, как у Яндекса), до 90 знаков по целому слову, уникальный (-2 при совпадении).
  В products.json: `catalog` (ключ раздела), `slug`, `legacy[]` (прежние адреса). path = /katalog/<url раздела>/<slug>.
- Все прежние адреса (Тильда и копия) → 301 на новые: сборка пишет dist/redirects.json; nginx при промахе
  (try_files … @legacy) спрашивает приёмник `/api/go?u=…` – тот отвечает 301 или отдаёт 404.html. Перезагрузка nginx не нужна.
- sitemap.xml – все индексируемые страницы с lastmod; /karta-sayta – дерево: Каталог → разделы → товары, Услуги, Акции, О компании, Документы.
- Маршруты – одно место src/lib/routes.ts, ссылки в коде – только через него.

## Шаг 2. SEO товара заполняется само (админка + сайт)
- Новый товар: адрес из названия (тот же транслит), каталог – первый отмеченный раздел.
- Title по умолчанию: «<Название> – купить в Болотном»; Description: «<Название> (<марка>) в магазине газового
  оборудования в Болотном, ул. Забабонова, 55А: характеристики, наличие, доставка, установка и подключение.»
  В редакторе поля заполнены сразу и видны; можно поправить руками. Сниппет – с новым адресом.
- Товары – Болотное (слово владельца); каталоги и услуги пока как есть (Новосибирск по спросу) – вопрос владельцу.

## Шаг 3. Боевой режим без GitHub (сервер)
- Источник данных в бою – сервер: /opt/gaz-mag/content (products.json, uploads/, своя история git на сервере).
- Админка сохраняет на сервер (`/api/admin/*`, тот же логин и пароль кабинета): чтение свежих данных, запись с проверкой
  версии (409 при чужой правке → повтор поверх свежих), загрузка фото. Окна «Подключить сохранение» нет.
- Сборщик – отдельный контейнер gaz-mag-builder (node + python + git): по сигналу собирает сайт из кода (/opt/gaz-mag/repo)
  + данных сервера, закрывает админку замком, включает выкладку атомарно (как receive.sh), пишет статус для админки.
- Код от разработчика: пуш в GitHub → Actions делает только «update» по урезанному ключу → сервер забирает код и пересобирает
  с данными сервера (правки админки не затираются).
- Пометка режима: src/lib/stage.ts STAGE = 'бой' | 'разработка' (в бою – сохранение на сервер, в шапке кабинета «Боевой сайт»).
  Правило в память: «выводим в бой» = STAGE 'бой' + сборщик на сервере, GitHub-ключ из админки убирается.
